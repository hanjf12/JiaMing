# 知识库维护说明

处理本目录时，先阅读 `purpose.md` 与 `schema.md`。

## 三层结构

1. `raw/`：输入事实与编辑资料。不要为了让回答更顺滑而改写原始引文。
2. `wiki/`：由 `npm run wiki:build` 编译的互链 Markdown 页面。
3. `runtime/`：浏览器使用的检索包、知识图谱与统计信息。

## 标准操作

### Ingest

把新资料放入 `inbox/`，记录来源、作者/篇名、获取日期和授权情况。审核后再合并到 `raw/`，随后运行：

```powershell
npm run wiki:build
npm run wiki:lint
```

### Query

从 `llms.txt` 或 `wiki/index.md` 进入，用 `rg`/`grep` 定位页面，优先读取具体页面及其一跳链接。核对完整原文时，先按 `corpus/catalog.md` 缩小目录，再检索上游 JSON。`corpus/vendor/` 被 Git 忽略，文件发现和原文检索统一使用 `--no-ignore`；不要用 `-uu` 读入隐藏的 `.git` 元数据，也不能因普通文件发现命令未列出它而判断未安装。回答必须区分原句直取、取意重组和编辑性建议。

### Lint

校验唯一 ID、必填来源、断链、孤立页、待核验标记和编译包一致性。发现问题时修正 `raw/` 或构建规则，不直接手改生成页。

## 安全边界

- 八字与五行只作用户主动提供的民俗偏好，不自动判断喜用神，不断言吉凶。
- 对户籍、医学、法律等高风险信息，只提示用户向权威机构核验。
- 不把用户导入的家族资料上传；浏览器自建库默认保存在 `localStorage`。
